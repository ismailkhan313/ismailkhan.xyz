* **Note**: The organizing claim worth keeping is the **committed artifact chain** — `intent.md` → `spec.md` → `plan.md` → the diff and its tests → the PR and its findings → the incident record → the next `intent.md`. Each stage ends by writing a file to version control and the next begins by reading it, which is what lets the playbook argue the old control objectives survive under new enforcement: the chain of commits *is* the audit trail. It is [context engineering](/context-engineering.md) applied to a process rather than a session.
* **Note**: The distinction the playbook is most careful about, and the one that reframes [Agent Skills](/agent-skills.md) as governance rather than productivity tooling: **a skill is an advisory control and a hook is a deterministic one**. A skill makes Claude likely to apply a policy while the code is written; nothing forces a session to comply. A policy that must always hold needs a hook behind it — the skill makes violations rare, the hook makes them close to impossible. Recorded on both the [skills play](</AI-Native SDLC/skills-as-institutional-knowledge.md>) and the [hooks play](</AI-Native SDLC/hooks-as-approval-gates.md>).
* **Note**: The [hooks play](</AI-Native SDLC/hooks-as-approval-gates.md>) carries the course's fullest artifact, a managed-settings file for a regulated enterprise, annotated key by key. Two points there are easy to miss and worth flagging: `sandbox` and `permissions.deny` enforce **one** objective at **two** layers (a tool-level deny on `WebFetch` doesn't stop a shell command reaching the network, and `credentials` covers what the file-tool deny rules miss for `~/.ssh` and `~/.aws/credentials`); and `allowManagedHooksOnly` silently invalidates the repo-level `.claude/settings.json` gate the same lesson shows first, so the gate has to be redefined in the managed file's own `hooks` block.
* **Note**: Three pages record the playbook's own framing against the [agentic design patterns](</Agentic Design Patterns/choosing-a-pattern.md>) vocabulary already in the wiki. Parallel Claude Code sessions are *not* a multi-agent system — no orchestrator, and the human is the only shared state — while subagents are the [parallel pattern](</Agentic Design Patterns/parallel.md>) with context isolation as the point. The [feedback loop](</AI-Native SDLC/feedback-loop.md>) is [iterative refinement](</Agentic Design Patterns/iterative-refinement.md>) with a deterministic evaluator rather than a model as judge. The sigma tier ladder in [closing the loop](</AI-Native SDLC/closing-the-loop.md>) is [human-in-the-loop](</Agentic Design Patterns/human-in-the-loop.md>) expressed as a threshold, with autonomy granted in proportion to how far the metric has moved.
* **Note**: Two caveats recorded on the [overview](</AI-Native SDLC/ai-native-sdlc.md>). This is a vendor's playbook for its own tools, and its value is the specificity rather than the thesis. And its measurement guidance is mostly proxy metrics readable from systems that already exist (Git timestamps, PR metadata, CI check runs, the OpenTelemetry export) — the leading indicators largely measure cycle time, and only the lagging ones (rework rate, change failure rate, escaped defects, DORA) speak to outcomes.
* **Note**: The [plan mode play](</AI-Native SDLC/plan-mode.md>) holds the course's only sustained treatment of legacy systems, which is the part most likely to matter in an enterprise adoption: for each artifact, name **one** system the source of truth and let the others hold a copy or a link, with the choice differing per artifact. The three configurations are the repo as truth, the legacy system as truth (Claude reading and writing back through an [MCP](/model-context-protocol.md) connector in the same session), and linkage — record ID in the artifact, commit SHA in the record — as the transitional minimum.
* **Note**: No diagrams yet. The course carries three figures (the moved bottleneck, line versus loop, and the play dependency graph); the reference file points at them by URL rather than embedding copies.
